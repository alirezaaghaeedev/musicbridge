# Contributing

Start with [local development](docs/development.md). The default workflow requires no real accounts. Keep changes focused, add meaningful regression coverage for behavior changes, and run lint, formatting, types, coverage, evaluation, docs/privacy checks, and the dry-run build before proposing a pull request.

Use synthetic fixtures. Never submit bot tokens, OAuth URLs/codes/tokens, private playlists, account IDs, deployment URLs, logs, or databases. Report vulnerabilities privately through [SECURITY.md](SECURITY.md). Do not run live provider tests against another person's resources.

Explain the problem, behavioral change, validation, and remaining risks in the pull request. Preserve matching safeguards, replay handling, and uncertain-write evidence. Discuss architectural changes before broad refactoring. AI-assisted contributions are welcome when reviewed, tested, and accurately attributed; contributors are responsible for the submitted material and its licensing.

There is no guaranteed review time or commercial support. See [the roadmap](docs/roadmap.md) for unresolved engineering work.
