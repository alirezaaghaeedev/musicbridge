# ADR-002: D1 for persistence

Retrospective record prepared for the public preview.

## Context

Accepted work, OAuth, settings, and mutation evidence need durable relational state.

## Decision

Use D1 transactions/batches and constraints as the source of truth.

## Alternatives evaluated now

KV, Durable Objects, or a separately hosted relational database.

## Consequences and trade-offs

Simple relational inspection and atomic ingestion; D1 round trips, platform dependence, and migration/recovery responsibility.

## Current status

Implemented.
